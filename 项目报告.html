四、根因深挖：百度首页改版

通过 DOM 探针脚本在有头/无头两种模式下取证，确认失败主因是被测页面结构性变化：

== 首页元素状态（Chrome 152 实测）==
count #kw: 1  →  displayed = False   # 旧版搜索框：存在但 0×0 隐藏
count #su: 1  →  displayed = False   # 旧版"百度一下"按钮：存在但 0×0 隐藏
#kw rect      = [0, 0, 0, 0]         # 整个旧版 form 被折叠
真实可见搜索框 = <textarea id="chat-textarea" class="chat-input-textarea ...">
真实提交按钮   = <button id="chat-submit-button">百度一下</button>
设置下拉菜单   = div#s-user-setting-menu.s-top-userset-menu（旧 .bdpfmenu 隐藏）

新版搜索流程实测：#chat-textarea 输入 + 回车 → 正常跳转 /s?wd=...，结果页标题 <关键词>_百度搜索，#content_left .result 有 6 条结果，断言链路全部可通。

关键修复 1：元素定位改用"任意可见元素"策略

# common/base_test.py — 修复前（只看第一个匹配，撞上隐藏元素就死等）
def find_element(self, by, value):
    return self.wait.until(EC.visibility_of_element_located((by, value)))

# 修复后：多个同定位器元素并存时，自动选中"可见"的那个
def find_element(self, by, value):
    elements = self.wait.until(EC.visibility_of_any_elements_located((by, value)))
    return elements[0]

关键修复 2：新增统一搜索入口，兼容新旧搜索框

# common/base_test.py — BaseTest.search()
def search(self, keyword):
    try:
        box = self.find_element(By.ID, "chat-textarea")   # 新版 AI 搜索框
    except Exception:
        box = self.find_element(By.ID, "kw")              # 旧版兜底
    box.send_keys(keyword)
    box.send_keys(Keys.ENTER)
    if "百度一下" in (self.driver.title or ""):            # 回车未生效时点击按钮兜底
        self.click(By.CSS_SELECTOR, "#chat-submit-button, #su")

关键修复 3：断言改为显式等待，消除时序竞态

# common/base_test.py — 标题断言：等待而非立即读取（修复"关于百度"读到空标题等）
def assert_title_contains(self, expected):
    try:
        self.wait.until(EC.title_contains(expected))
    except Exception:
        raise AssertionError(f"页面标题 '{self.driver.title}' 不包含 '{expected}'（等待超时）")

# 新增：点击后自动跟随跳转（无论新标签页还是当前页跳转都能切换到位）

六、遗留风险与建议

  • 被测对象依赖第三方线上页面：百度首页仍在持续迭代，本次适配的选择器（如 #chat-textarea、.pfpanel-bd）未来可能再次失效。建议定期（如每月）跑一次全量回归及早发现 UI 变更，BaseTest 中已通过"可见元素策略 + 多候选选择器（逗号分隔旧/新选择器）"提高容错。
  • 执行耗时偏长（全量约 33 分钟）：主要开销为每条用例独立启动浏览器 + 隐式等待 10 秒。建议后续引入 pytest-xdist 并行执行，或对同模块用例复用浏览器会话，可将耗时压缩至三分之一。
  • 未登录态限制：搜索设置弹窗提示"请启用浏览器 Cookie 或登录"，设置项无法保存验证，当前用例仅验证弹窗能打开，属合理边界。
  • 反爬风险：项目已含 webdriver 指纹隐藏配置，高频运行仍可能触发百度安全验证。建议控制执行频率，必要时接入代理或降频调度。
  • 建议补充：为 BaseTest 关键方法补充单元级测试；在 CI（如 GitHub Actions）中配置定时冒烟运行，失败自动通知。
